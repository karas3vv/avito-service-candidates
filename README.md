# Поиск объявлений услуг Авито

Решение тестового задания: по запросу пользователя найти до 50 объявлений, которые стоит передать на ранжирование. Основная метрика — Recall@50, то есть доля выбранных пользователем объявлений, попавших в ответ.

Поиск работает в два этапа. Сначала TF-IDF и BM25 собирают примерно 500 кандидатов. Затем LightGBM выбирает из них 50 с учётом текста, локации, фильтров и характеристик объявления.

На локальной проверке по 400 запросам получен **Recall@50 = 0,92375**. Это результат на отложенной части train; качество на скрытом бенчмарке может отличаться.

## Запуск

Решение проверено на Python 3.10. Нужно скачать [архив с данными](https://disk.yandex.ru/d/sNhfo0YOjGtufg) и положить `train.parquet`, `benchmark_items.parquet` и `benchmark_queries.parquet` в папку `data/`.

```bash
git clone https://github.com/karas3vv/avito-service-candidates.git
cd avito-service-candidates
mkdir -p data
unzip /path/to/dataset.zip -d data/
python -m pip install -r requirements.txt
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=4 python src/solution.py
python scripts/validate_answer.py
sha256sum -c answer.sha256
```

Скрипт строит индексы, обучает модель и сохраняет `answer.csv` в корне проекта. Вместе с ним записываются модель в `model.txt` и результаты проверки в `metrics.json`.

Индексы и признаки сохраняются в `.cache_v2/`. Если они уже построены, повторно обучить модель можно командой `python src/solution.py --stage train`. Для пересчёта с нуля нужно указать новый каталог через `--cache-dir`. Кэш занимает около 1,2 ГБ, исходные данные — ещё около 650 МБ.

При повторном обучении на сохранённых признаках получился побайтово тот же CSV. Предсказания также проверены после загрузки модели из файла. Команда `sha256sum -c answer.sha256` проверяет совпадение с ответом в репозитории.

## Какие данные используются

В `train.parquet` находятся положительные пары «запрос — выбранное объявление». Поиск выполняется по `benchmark_items.parquet`, а ответы формируются для запросов из `benchmark_queries.parquet`.

Основные признаки:

- **Текст запроса, заголовок и описание.** Услуга не всегда названа в заголовке теми же словами, что в запросе, поэтому поиск учитывает описание и разные формы слов.
- **Фильтры запроса и параметры объявления.** Помогают различать похожие услуги и учитывать уточнения пользователя.
- **Локация и координаты.** Используются совпадение локаций, расстояние до медианного центра поисковой локации и статистика выборов объявлений в других локациях.
- **Подкатегория.** По train рассчитывается, какие подкатегории выбирали для такого же или похожего запроса.
- **Рейтинг, число отзывов, цена, длина заголовка и доступность связи.** Эти признаки помогают выбирать среди объявлений с похожим текстом.

Идентификаторы не подаются в LightGBM. Прямые частоты кликов по паре и популярность конкретного объявления тоже исключены из его признаков: при выбранной схеме валидации они могли бы дать искусственную подсказку. Категория поиска и флаг доставки учитываются при группировке разметки, но не входят в итоговую модель.

## Как устроен поиск

TF-IDF используется для слов и биграмм заголовка с параметрами, символьных n-грамм заголовка, слов описания и параметров. BM25 отдельно ищет по заголовку, первым 3 000 символам описания и параметрам. Перед BM25 русский текст проходит стемминг Snowball.

Результаты этих поисков объединяются с кандидатами из поисковой локации. Так в набор могут попасть объявления, которые хорошо совпадают только по одному из признаков — например, по описанию или по месту оказания услуги.

Дальше LightGBM LambdaRank оценивает 32 признака каждой пары и оставляет 50 объявлений. Число деревьев подбиралось на отдельной выборке из 400 запросов: из значений от 50 до 300 с шагом 50 выбрано 250. Остальные параметры и seed указаны в коде.

Используются NumPy, pandas, PyArrow, SciPy, scikit-learn, LightGBM, snowballstemmer и joblib. Версии закреплены в `requirements.txt`. Предобученных моделей и обращений к внешним API нет.

## Проверка качества

Для обучения модели используются 2 398 запросов, для выбора числа деревьев — 400, для итоговой проверки — ещё 400. Во всех частях есть редкие и частые фразы. После нормализации регистра и пробелов тексты обучающих запросов не пересекаются с отложенными.

Для выбранного контекста запроса разметка включает все известные выбранные объявления, которые есть в корпусе. Из статистик кликов удаляются все повторения этих пар «текст запроса — объявление», в том числе в других контекстах. Итоговая проверочная часть не участвует в обучении и выборе числа деревьев.

Дополнительно проверены 350 запросов, для которых правильные объявления не встречались среди обучающих ответов LightGBM. На них Recall@50 равен **0,92286**. Подробные значения находятся в `metrics.json`.

У этой проверки есть ограничение: она построена по объявлениям, которые встречаются и в train, и в корпусе бенчмарка. Их распределение может отличаться от скрытой разметки.

## Что показал разбор ошибок

Текстовый поиск чаще пропускает объявления, если услуга описана другими словами или упомянута только в описании. Для таких случаев используются символьные n-граммы, стемминг и поиск по описанию. BM25 вместе с географическим сигналом даёт Recall@50 около 0,727 на той же проверочной выборке.

Ещё одна сложность — выбор между текстово похожими объявлениями из разных локаций или с разными параметрами услуги. Обучаемая модель учитывает эти признаки совместно и доводит Recall@50 до 0,924.

Полнота набора перед LightGBM составляет 0,96625. Значит, часть промахов возникает ещё на этапе поиска кандидатов, а ещё 0,0425 среднего Recall теряется при сокращении набора до 50. Здесь остаётся пространство для улучшения как самого поиска, так и отбора кандидатов.

## Файлы проекта

- `src/solution.py` — подготовка выборок, признаки, обучение и предсказания.
- `src/retrieval.py` — TF-IDF и BM25.
- `scripts/validate_answer.py` — проверка формата CSV и идентификаторов.
- `answer.csv`, `answer.sha256` — ответ и его контрольная сумма.
- `model.txt`, `metrics.json` — обученная модель и результаты проверки.
- `data/`, `.cache_v2/` — данные и кэш, исключённые из Git.
