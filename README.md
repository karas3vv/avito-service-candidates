# Кандидаты объявлений для поиска услуг Авито

Решение тестового задания по кандидатогенерации: для каждого запроса из `benchmark_queries.parquet` возвращает до 50 идентификаторов объявлений из `benchmark_items.parquet`. Метрика задания — Recall@50.

## Структура

- `src/solution.py` — воспроизводимый расчёт с комментариями.
- `scripts/validate_answer.py` — независимая проверка формата результата.
- `answer.csv` — готовый ответ на 2 452 запроса.
- `data/` — исходные Parquet-файлы. Они есть локально, но исключены из Git из-за размера.

## Запуск

Нужен Python 3.10+ и три файла в `data/`: `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet`.

```bash
python -m pip install -r requirements.txt
python src/solution.py
python scripts/validate_answer.py
```

Скрипт сохраняет `answer.csv` в корне проекта. Он использует только локальные библиотеки и данные, без внешних API. Исходный набор: [публичный архив задания](https://disk.yandex.ru/d/sNhfo0YOjGtufg).

## Подход

1. TF-IDF по словам в заголовке и параметрах объявления, по символьным n-граммам заголовка, по словам описания и по параметрам объявления.
2. Статистика выбранных объявлений из `train.parquet`: распределение подкатегорий для точного и похожих запросов, а также распределение локаций для поисковой локации.
3. Взвешенная сумма текстовых, географических и поведенческих сигналов. В ответ берутся 50 объявлений с наибольшим итоговым баллом.

Для локальной проверки из train исключаются 400 выбранных объявлений с различными поисковыми фразами. На этой отложенной выборке получен **Recall@50 = 0,555**. Это ориентир по одиночным выборам, а не оценка скрытого бенчмарка.

Использованы открытые библиотеки NumPy, pandas, PyArrow, SciPy и scikit-learn. Предобученные модели и внешние сервисы при расчёте не используются.
