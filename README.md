# Кандидаты объявлений для поиска услуг Авито

Решение тестового задания по кандидатогенерации: для каждого запроса из `benchmark_queries.parquet` возвращает 50 идентификаторов объявлений из `benchmark_items.parquet`. Метрика задания — Recall@50.

## Структура

- `src/solution.py` — полный расчёт с комментариями и локальной оценкой.
- `scripts/validate_answer.py` — независимая проверка формата и идентификаторов.
- `answer.csv` — готовый ответ на 2 452 запроса.
- `data/` — исходные Parquet-файлы. Они не входят в Git из-за размера, но доступны в [публичном архиве задания](https://disk.yandex.ru/d/sNhfo0YOjGtufg).

## Как воспроизвести ответ

Нужен Python 3.10 и три файла `train.parquet`, `benchmark_queries.parquet`, `benchmark_items.parquet` в папке `data/`.

```bash
git clone https://github.com/karas3vv/avito-service-candidates.git
cd avito-service-candidates
mkdir -p data
# Скачайте dataset.zip по ссылке выше, затем:
unzip /path/to/dataset.zip -d data/
python -m pip install -r requirements.txt
OPENBLAS_NUM_THREADS=2 OMP_NUM_THREADS=2 python src/solution.py
python scripts/validate_answer.py
sha256sum answer.csv
```

Контрольная SHA-256 сумма `answer.csv`: `9989b0ff2b13e717a6c5c5dfaa1b6e7d3505ae4ed1ef544b6af59d2ea5172471`. Полный повторный запуск из этого проекта дал ту же сумму, что и файл в коммите. Скрипт работает локально, без обращений к внешним API. Запуск может занять несколько минут и требует памяти для TF-IDF индексов.

## Данные и признаки

- `search_query` сопоставляется с заголовком, описанием и параметрами объявления. Короткий запрос часто не совпадает дословно с заголовком, поэтому используются и слова, и символьные n-граммы.
- `search_infm_params_text` сопоставляется с `item_infm_params_text`, чтобы учитывать выбранные пользователем фильтры.
- `search_location_id` и `item_location_id` дают основной географический сигнал. Из выбранных пар train также считается распределение локаций объявлений для каждой поисковой локации: это помогает, когда релевантное объявление находится в соседней локации.
- `item_microcat_id` используется через распределение подкатегорий выбранных объявлений для точного и похожих текстов запроса. Близость текстов запросов считается по символьному TF-IDF.
- `item_rating_reviews_count` даёт небольшой сигнал качества. Частота выбора конкретного объявления по тому же тексту запроса используется как слабый дополнительный сигнал.

Цена, рейтинг, координаты и флаги способов связи не используются. `search_category` почти постоянна в train; целевая задача здесь — полнота поиска среди объявлений услуг, поэтому эти поля не вошли в текущую формулу.

## Алгоритм

Используется TF-IDF из scikit-learn в четырёх представлениях: слова и биграммы заголовка с параметрами, символьные n-граммы заголовка, слова и биграммы описания, слова и биграммы параметров. Их косинусные сходства складываются с географическим и поведенческим сигналами. Итоговый балл считается для объявлений корпуса; выбираются 50 идентификаторов с наибольшим баллом. Весовые коэффициенты указаны в `src/solution.py`. Нейросетей и внешних моделей нет.

Использованы открытые библиотеки NumPy, pandas, PyArrow, SciPy и scikit-learn; версии зафиксированы в `requirements.txt`.

## Проверка качества и анализ ошибок

Для локальной проверки из train исключены 400 выбранных объявлений, присутствующих в корпусе бенчмарка: 250 с редкими фразами (не более 5 вхождений) и 150 с частыми. Фразы в отложенных строках различны; остальные строки с той же фразой могут оставаться в обучающих данных. Результат — **Recall@50 = 0,555** (222 попадания из 400). Это оценка по одному выбору на запрос, а не результат скрытого бенчмарка.

| Срез отложенной выборки | Recall@50 | Число примеров |
| --- | ---: | ---: |
| Полный текст запроса есть в заголовке | 0,939 | 49 |
| Полного текста запроса нет в заголовке | 0,501 | 351 |
| Та же локация | 0,564 | 314 |
| Другая локация | 0,523 | 86 |
| Редкий запрос | 0,548 | 250 |
| Частый запрос | 0,567 | 150 |

Главный обнаруженный тип ошибок — лексическое несовпадение: объявления с перефразированным или более общим заголовком находятся хуже. Символьные n-граммы, описание и параметры частично смягчают его, но не устраняют. Промахи чаще встречаются и при несовпадении локации; поэтому учитывается статистика переходов между локациями и в кандидаты допускаются объявления вне точной локации. Для редких фраз мало поведенческих примеров, поэтому распределение подкатегорий сглаживается по похожим запросам. Эти срезы пересекаются и не складываются в общее число ошибок.

Отдельная проверка `scripts/validate_answer.py` подтверждает: ровно 2 452 строки, все `query_id` из бенчмарка, не больше 50 уникальных объявлений на запрос и все `item_id` в корпусе.
